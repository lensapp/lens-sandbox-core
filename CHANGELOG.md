# Changelog

All notable changes to `lens-sandbox-core` will be documented in this file.

This project will use versioned releases once public releases begin. Until then, the API should be treated as pre-1.0 and subject to change.

## [Unreleased]

- `proxy::serve_explicit` judges and serves one connection from a client that was told to use a proxy, with the caller given, as `proxy::serve_egress` does for a transparent one.
- A host that a `forward` route (mTLS client certificate) sends direct goes through the MITM pipeline, as every other intercepted host does. The pipeline judges the request, and then dials the route's `dialAddr` with its client certificate, `tlsServerName` and CA, and sets `upstreamHostHeader` as before. Thus the route's HTTP rules, the ask gate, credential injections, token answers and `llm` routes now apply to such a host, and a transparent TLS connection or an absolute-form `https://` request to it is forwarded, not refused with `403`. An injected or signed credential covers the head with the `upstreamHostHeader` Host. When a route sets `upstreamHostHeader`, the workload's `Authorization` header is still dropped and does not leave the proxy, except on a signed host, where the signer replaces it; it is now dropped before the credential gate reads the head, so a placeholder in it is not held for a prompt. A request is audited as on any other intercepted host (`<METHOD> <host><path>`, `mitm: true`), not as `TLS_BRIDGE <host> -> <dialAddr>`. `mitm::handle_tls_bridge` is removed, and `mitm::UpstreamMode::DirectTls` has a `forward` field. A host on `upstream` transport goes through the upstream proxy without the certificate: on the `CONNECT` and absolute-form `https://` doors as before, and on the transparent TLS door, which refused such a host with `transparent-not-supported:client-cert`, now too.
- A policy's files are placed by whoever owns the workload's filesystem, with or without a proxy in that process: `client::PlacedFiles` replaces `ProxyState::previous_policy_files` and `sandbox_creds`; `client::run` and `apply_local_policy` take a `&PlacedFiles`, `ProxyServer::new` no longer takes the credentials, and `temp_files::refresh_policy_files` takes the mounts it may place a file on.
- Add a host mode for an embedder that judges a guest's egress from its own process. `ProxyState::for_host(ca, bootstrap_dns_allowlist)` builds the state without listeners; it intercepts with the CA the embedder owns and never installs it, or a frame's `proxyCaCert`, into the system trust store, so the embedder hands the guest `ca_cert_pem` itself. `connect_audit` is public. An embedder that writes the audit itself calls `ProxyState::audit_written` for each message it wrote or discarded, so the state stops holding it, and `ProxyState::unwritten_refusals` counts what it still holds. `dns::MAX_INFLIGHT_QUERIES` is public, so an embedder can size its own DNS path to it.
- Add the `egress::Egress` port, which decides how the judge dials upstream: `sock_mark::MarkedEgress` in the guest (marked past the nftables cage, as before) and `egress::HostEgress` on a host (plain sockets, and a refusal of the host's own addresses; `is_own_address` moved here from the supervisor crate). The SSRF floor (`is_disallowed_egress_ip`, `is_link_local`) and the resolving dials (`connect_tcp_resolve`, `connect_tcp_egress`, `connect_tcp_egress_where`) moved from `sock_mark` to `egress` and take the port, which also resolves the name (with `resolver::resolve_first` unless it says otherwise). `sock_mark::bind_udp` is now `pub(crate)`.
- Add `client::apply_policy_frame`, which applies one `policy` frame to a host state and returns an `AppliedPolicy` with the frame's `env` and its `files`, which the embedder places where the workload runs: the host proxy writes nothing to its own disk. A frame it cannot read is a `PolicyFrameError::Malformed`, and in the guest such a frame keeps the files the last frame placed.
- `privilege::Confinement` replaces the `is_root` flag on `ChildSpec`, `ExecManager::new`, `with_launcher`, `spawn_pty`, `apply_privilege_drop`, `privilege_drop_for` and `CoreConfig`: `Guest` (a root parent built the cage; a root child drops its capabilities), `Host` (the host judges egress; a root child keeps what its parent has but takes the group it asked for, as `PrivilegeDrop::KeepRoot { gid }`, and nothing is reported) and `Unprivileged` (an unprivileged parent; as `is_root: false` before). `Confinement::of_this_process` gives `Guest` for a root process and `Unprivileged` otherwise.
- Initial open-source repository hygiene and contribution documentation.
- Add the `lens-sandbox-runtime` and `lens-sandbox-supervisor` crates, which run a sandbox with no root in the workload.
- Keep an exited exec, with its scrollback and its `exec_exit` / `exec_error`, until the client sends the new `exec_ack` frame or five minutes pass. A reattach to an exited exec gets `exec_attached`, the scrollback, then the final frame.
- Add `ExecManager::detach_for_shutdown` and split `ChildExit` into `Finished` and `Stopped`, so a supervisor can tell a workload exit from a stop signal.
- Bump the protocol date to 2026-10-09.
- The audit dedup folds a failure event only into the same refusal: one with another reason, port, path or caller is sent, so a consumer never files it under the wrong destination.
- A dedup window that folded repeats of a failure event now closes with one summary event: the folded event with `metadata.summary: true`, `metadata.suppressed` (the repeats folded) and `metadata.last_suppressed_at` (when the last of them was refused, RFC 3339), so a consumer can count every refusal. A summary is sent when its window closes, not when the next refusal arrives.
- Add the policy-message field `proxyUpstreamPlainHttp` (`"tunnel"` or `"forward"`). With `"forward"`, the proxy sends a plain-HTTP request to the upstream proxy as a forward-proxy request in absolute form, not through a `CONNECT host:80` tunnel. An absent or unknown value keeps `"tunnel"`.
- Bump the protocol date to 2026-10-13.
- A refused DNS lookup names its caller in `actor.process` (`file.path` and `lineage`), as a proxy refusal does, so a consumer can tell which `binaries` rule refused it. A lookup with no attributable caller, or under a policy with no `binaries` rule, has no actor.
- A refusal or dedup summary the audit channel does not deliver, because it is disconnected or its connection fails before the event is written, is held and sent first when the channel reconnects, so a reconnect no longer loses the refusals it counted. A held refusal is sent as a summary that counts it, dated when it was refused, folded with any later summary of the same refusal. One summary is held per refusal, up to 1024 of them; refusals past that are counted in one summary with `action` and `metadata.reason` set to `audit-overflow`. A refusal from the approval gate (`user-denied-once`, `decision-timeout`, …) is held the same way and is never folded, so each one is counted.
- The proxy door serves an absolute-form `https://` request (`GET https://host/path HTTP/1.1` in the clear, as BusyBox `wget` sends one) instead of closing the socket on it. It is admitted as the `CONNECT host:443` it names, with the same route, card and Always Allow, then judged and relayed by the MITM pipeline, so HTTP rules, credentials, `llm` routes and the audit apply. A request the door cannot read is answered with 400, and a destination the proxy never dials (loopback, link-local, `localhost`) with 403 on every door, instead of a closed socket, and audited as `blocked-destination` as the transparent door audits it.
- An exec can limit its output: with the new `outputWindow` on `exec_attach` and `exec_reattach`, the supervisor sends at most that many output bytes ahead of the client's new `exec_output_credit` frames, so a child that writes faster than the client reads waits in `write` instead of filling memory. The new `exec_release` frame lets a client that goes away keep the exec running, with no limit, for a reattach. An exec with no `outputWindow` has no limit, as before.
- A policy refusal says the sandbox refused it. Every door answers it with `403 Forbidden by sandbox policy`, an `X-Sandbox-Blocked` header carrying the reason (`policy-deny`, `binary-not-allowed`, `ask-declined` or `credential-gate`), `Proxy-Status: sandbox; error=http_request_denied; details="<reason>"`, and a one-line `text/plain` body: `Blocked by sandbox egress policy: GET api.example.com/v1/foo (reason: policy-deny). This is not a response from api.example.com.` An embedder names its product with the new `ProxyState::set_block_label`: with `Lens Agents`, the status reads `403 Forbidden by Lens Agents sandbox policy` and the body `Blocked by Lens Agents sandbox egress policy: …`. The label is set once, and one that is not printable ASCII, is blank or has surrounding spaces, or is longer than 64 bytes is refused. `Proxy-Status` names `sandbox` whatever the label. The body names the method, the host and the path without its query, with any credential placeholder in the path redacted, and nothing else. This covers the plain-HTTP, absolute-form `https://` and transparent HTTP doors, a refused `CONNECT`, a request an intercepted session refuses, and the AWS re-sign path. A destination the proxy never dials is refused the same way, as `policy-deny`.
- Most clients never show the answer to a `CONNECT`, so a `CONNECT` that `egress.http` refuses (`policy-deny`, `binary-not-allowed`, `ask-declined`) is now accepted with `200`: if the client then speaks TLS, the proxy completes the handshake with a sandbox-CA certificate for the `CONNECT` host, reads one request head and answers it with the refusal, so curl, Node, Python and git show it. The destination is never dialled, and the head is not logged; its method and path are audited (see the entry on refused HTTPS requests below). A client that does not start TLS, or sends nothing within 2 s, is disconnected, and the TLS answer is bounded at 10 s. A host no certificate can be made for is refused on the `CONNECT` as before. The transparent TLS door answers a deny, a `binaries` miss or a declined card the same way, inside the session whose SNI it peeked, instead of closing it. A client that does not trust the sandbox CA now sees a certificate error in place of the refused `CONNECT`. An `egress.tcp` refusal, which opts out of interception, a destination the proxy never dials, and a transparent connection without SNI are still refused without TLS.
- A refusal by the upstream proxy is relayed as a block instead of a `502 Bad Gateway`: when the upstream answers a tunnel with `403` and `X-Sandbox-Blocked: upstream-policy`, the client is told with the block response and reason `upstream-policy` — inside the tunnel on the `CONNECT` and transparent TLS doors, in the clear on the plain-HTTP and absolute-form `https://` doors, and inside the session for a host whose token requests the proxy answers. It is audited as a `failure` with status 403. Any other refusal by the upstream is still a 502.
- An intercepted response loses any `X-Sandbox-Blocked` and `Proxy-Status` field the origin sent (a CDN's `Proxy-Status` included), so an origin cannot pass its own answer off as a sandbox block. Interim `1xx` heads (`100 Continue`, `103 Early Hints`) and a `101 Switching Protocols` lose them too; everything else in those heads, the `101`'s `Connection` and `Upgrade` included, is relayed as sent. An `llm` translation writes its own head, so a backend's fields never reach the client either. A response the proxy relays without reading it keeps them: the plain-HTTP door, and `CONNECT` and `egress.tcp` splices. Known gap: a dial the `egress.tcp` table refuses after a `CONNECT` was already answered with `200` (an address a CIDR deny covers, resolved from a name `egress.http` admitted) still closes the connection without the block response.
- The orphan reaper finds the children of the supervisor from `/proc/<pid>/stat`. Before, it read `/proc/<pid>/task/<tid>/children`, which a kernel without `CONFIG_PROC_CHILDREN` (such as a Kata Containers guest) does not have, and it then reaped no orphans.
- The orphan reaper also finds a child whose name is not UTF-8. The kernel cuts a name to 15 bytes, which can split a UTF-8 character, and the reaper skipped such a child, so its zombie stayed.
- The audit record of a request an intercepted session forwards now carries what the origin answered: `upstream_status_code`, the status of the final answer, and for a `4xx` with a JSON body of at most 16 KiB, `upstream_error_code`: the body's `error.code` (OpenAI's shape), or `error.type` in Anthropic's envelope (`{"type":"error","error":{...}}`). The body is read as it is relayed and reaches the workload unchanged; a compressed or longer body is not read. The proxy's own `status_code` is still not set on such a record, so a consumer can tell the proxy's decisions from the origin's answers. The record is sent when the answer's head arrives (for a `4xx` it reads, when its body ends), or with no answer when the origin gives none. A request an `llm` route translated and the plain-HTTP door are not changed.
- A request an intercepted session forwards is sent once more when the origin refuses it `401` and a header credential it carried has another value since it was sent, as when the host renews a key its issuer retires at once. The second answer is relayed whatever it is, so a request is sent at most twice. It is sent again only when the proxy still holds all of it: no body, or a body it read whole for a rule; no credential in the body; no upgrade or `llm` translation; no interim answer already relayed to the workload; and a connection it can open again (a direct dial, or a tunnel it opens on demand). Its audit record has `metadata.resent_after_renewal: true` and the second answer's status.
- A `CONNECT` the proxy relays without intercepting it dials the destination before it answers. When the dial fails (the name does not resolve, the address refuses or cannot be reached, or an `egress.tcp` rule refuses the resolved address), the client gets `502 Bad Gateway` with a one-line `text/plain` body naming the target and the error, instead of a `200` and a tunnel that closes, which curl reported as a broken pipe and Python as an SSL EOF. An `egress.tcp` splice that cannot dial says the same. A failed dial on the `CONNECT` door, to the destination or to the upstream proxy, is logged at `warn`. A `CONNECT` the proxy intercepts still answers `200` first: it accepts the client's TLS inside the tunnel, and dials only once it has read and judged the request.
- A refused HTTPS request is audited with its method and path. A `CONNECT` or transparent TLS connection that `egress.http` refuses (`policy-deny`, `binary-not-allowed`) or the upstream proxy refuses (`upstream-policy`) gets one `failure` event, sent once the proxy has answered the request head it read inside the TLS session: `method` is the request method, `path` the path without its query, with any credential placeholder redacted as in the block body and cut to 256 bytes on a UTF-8 boundary, and `action` is `<METHOD> https://<host>:<port><path>`, with the port the connection was made to, as on the AWS re-sign path, so a refusal of `api.internal:8443` reads `GET https://api.internal:8443/v1/foo` and is not counted with one of `api.internal:443`. This includes a host whose token requests the proxy answers, whose tunnel through the upstream opens only for a request it forwards, on every door. When no head is read (the client does not start TLS, sends nothing within 2 s, does not trust the sandbox CA, closes, or has not sent a request within the 10 s bound, or no certificate can be made for the host), the event is the one sent before: `method: "CONNECT"` and no `path`. `host`, `result`, `status_code`, `metadata.reason` and the actor fields do not change, and the audit dedup counts each method and path apart. For Lens Agents and any consumer that counts these events: the event now comes after the TLS handshake and the answer, not when the `CONNECT` arrives, so milliseconds later and at worst 10 s. The answer to the workload does not change. A declined card is still audited by the answer, and an `egress.tcp` refusal and any other refusal on the absolute-form `https://` door still name the destination only. No policy schema, wire type or protocol date change.
- The audit dedup window is now 1 s, not 10 s. A repeated refusal is folded for at most 1 s, and its summary event is sent when that window closes, so a host counts it within 1 s. For Lens Agents and any consumer that counts these events: a retry storm now gives one summary per refusal each second, so up to 10 times more summary events.
- A `CONNECT` whose dial is refused after its name resolves is answered as a refusal: `403` with `X-Sandbox-Blocked: policy-deny`, not a `502`. The refusal is audited as `blocked-destination` when the address is loopback, link-local or unspecified, and as `policy-deny` on the resolved address (`CONNECT 10.1.2.3:443`) when an `egress.tcp` rule refuses it, so a consumer matches it against the CIDR rule that refused it, not the name the client sent. Only these two refusals are answered with `403`: a `connect` that the operating system refuses (`EACCES`, `EPERM`) is a failed dial. A `CONNECT` whose dial fails gets a `502` with an RFC 9209 `Proxy-Status` error (`dns_error`, `connection_timeout`, `connection_refused` or `destination_unavailable`), and an egress dial gives up after 30 s instead of the operating system's connect timeout.
- An absolute-form `https://` request (`GET https://host/path HTTP/1.1` in the clear) whose dial is refused after its name resolves is audited as the `CONNECT` door audits it: a `failure` 403 with `metadata.reason` `blocked-destination` for a loopback, link-local or unspecified address, and `policy-deny` on the resolved address (`CONNECT 10.1.2.3:443`) when an `egress.tcp` rule refuses it. It was audited as an `error` 403 with no reason, on the name. A `connect` the operating system refuses (`EACCES`, `EPERM`) is now a failed dial, not a refusal, and a dial that fails on this door gets the same `502` with a `Proxy-Status` error and a body naming why as the `CONNECT` door, instead of an empty `502`. On a host that judges for a guest, a dial to the host's own address is a `blocked-destination` refusal on both doors, which names no address, instead of a `502` whose body named the host's address. A TLS handshake that fails after the dial keeps the plain `502`.
